Vector Access Control Leaks: Why Post-Retrieval Filtering is a Security Lie

AI agents query databases at machine speed. Learn why post-retrieval filtering and embedding inversion leak data, and how to enforce zero-trust storage RBAC.

A zero-trust data substrate is the architectural practice of enforcing cryptographic access control directly inside the storage engine rather than at the application boundary. Access control designed for humans assumes the attacker cannot see the query interface; autonomous AI agents invalidate that assumption completely by executing machine-speed queries across raw backend interfaces.

A person using an internal enterprise application is constrained by the UI screens built for them. They see specific fields, filter what the search dropdown permits, and the backend application controls which rows to fetch. Decades of enterprise security quietly depend on this model: coarse role-based access control (RBAC) at the application layer because the application controls the questions.

An autonomous AI agent has no screens. It composes queries directly, at machine speed, across whatever database interfaces its credentials reach. And unlike a person, it can be persuaded—by hidden text in a PDF, a comment in a support ticket, or an injected prompt—to execute queries nobody intended.

The exfiltration path isn't the text prompt; it is the data retrieval payload. If you don't control the storage engine, you can't guarantee privacy.
