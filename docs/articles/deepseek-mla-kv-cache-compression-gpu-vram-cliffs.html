Multi-Head Latent Attention (MLA): 93% KV Cache Compression

Multi-Head Latent Attention (MLA) compresses Transformer KV caches by 93.3% via low-rank joint projection and decoupled RoPE, multiplying GPU batch sizes by 5.6x.

Imagine a regional dispatch office where 128 operators each keep an identical, 5,000-page printed phonebook on their desk. Every time a new customer calls, every operator prints and binds another page, quickly filling the room from floor to ceiling. Multi-Head Latent Attention (MLA) replaces those 128 bulky phonebooks with a single, 1-page compressed index card stored in a central drawer, cutting High-Bandwidth Memory (HBM) cache consumption by 93.3% on production Graphics Processing Unit (GPU) clusters.

When you serve frontier Large Language Models (LLMs) across 64,000 to 128,000 token context windows, model weights aren't your primary memory bottleneck. Your real enemy is the Key-Value (KV) cache. That cache grows linearly with every token and every concurrent user session.

In classic Multi-Head Attention (MHA), a 671-billion-parameter model with 128 attention heads stores separate 128-dimensional Key ($K$) and Value ($V$) tensors for every head across all 61 layers. At 16-bit floating-point (BF16) precision, a single token consumes 4.19 MB of GPU Video Random Access Memory (VRAM). One 128K-token conversation demands 536.8 GB of KV cache alone, overflowing an entire 8x NVIDIA H100 (640 GB) node before a second user can connect.

Meta's Grouped-Query Attention (GQA) and Multi-Query Attention (MQA) tried to shrink this footprint by forcing 8 or 16 query heads to share a single Key-Value head. While GQA cuts cache size by 75% to 87.5%, it permanently discards expressive per-head representational capacity. You save memory, but reasoning accuracy on complex multi-document retrieval drops.
