Disaggregated Prefill-Decode in vLLM: NixlConnector Guide

Decoupling vLLM V1 prefill and decode pools via NVIDIA NIXL (NixlConnector) and LMCache cuts p99 inter-token latency by 74% and boosts GPU goodput 2.4x.

Imagine a grocery store routing 64-pallet freight deliveries and ten-item express shoppers onto the exact same checkout belt: every time a truck arrives, forty-eight shoppers mid-checkout freeze for a full second. Running Large Language Model (LLM) prompt ingestion (prefill) and token streaming (decode) on one Graphics Processing Unit (GPU) node causes that exact stall. Disaggregated Prefill-Decode via NVIDIA Inference Xfer Library (NIXL) and LMCache eliminates it, cutting p99 Inter-Token Latency (ITL) by 74% and boosting GPU goodput 2.4x.

Continuous batching engines like vLLM and SGLang transformed LLM serving by interleaving incoming prompt requests with active token-generation streams inside unified PagedAttention memory. That colocated design works cleanly when prompts stay short (512 to 2,048 tokens), and you don't notice contention at low concurrency. Once enterprise Retrieval-Augmented Generation (RAG) and coding agents push input contexts to 32,000 or 64,000 tokens, colocated scheduling can't hide the underlying hardware physics mismatch.

LLM inference consists of two fundamentally opposite hardware phases:

- The Prefill Phase (Compute-Bound): Processes all 64,000 input prompt tokens in parallel to populate the initial Key-Value (KV) cache. A single long-context prefill saturates 100% of GPU Streaming Multiprocessors (SMs) and Tensor Cores for 700 ms to 1,200 ms, leaving High-Bandwidth Memory (HBM) bandwidth underutilized.
